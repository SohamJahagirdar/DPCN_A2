## 1. The project in one page

The course (instructor: **Prof. Chittaranjan Hens**) maps the research output of 43+ Indian institutions across 30 groups. **Group 18 covers IISc Bangalore and TIFR Mumbai only.** TIFR's other centres (NCBS, NCRA, ICTS, TIFR Hyderabad, TIFR-CAM, HBCSE) are deliberately excluded. Do not add other institutions.

**Required deliverables** (from the instruction note), all generated by this repo:

| Deliverable | Where | Status |
|---|---|---|
| Dataset `group18_data.csv` (14 required columns + extras) | `outputs/` | ✅ |
| `citation_network.csv`, `authorship_network.csv`, `indian_connections.csv` | `outputs/` | ✅ |
| Interactive dashboard (incl. citation and co-authorship network visualisations) | `dashboard/index.html`, published by GitHub Pages | ✅ |
| Statistics report (≤ 10 slides or ≤ 5 pages) | see section 12 | ⚠️ draft exists, numbers outdated |

**What the code does:**
1. Downloads every 2016–2026 paper of IISc and TIFR Mumbai from **OpenAlex**.
2. Identifies faculty using the official rosters.
3. Adds journal quality from **SCImago** and **CORE**, and reputable-journal status from the **Nature Index**.
4. Builds citation and co-authorship networks.
5. Measures the connections and impact on the rest of Indian science.
6. Produces the CSV deliverables and an offline-capable HTML dashboard.

**Headline numbers** (full detail in README §3.3):

| | IISc | TIFR Mumbai | Both |
|---|---|---|---|
| Papers 2016–2026 | 35,818 | 7,752 | 42,725 (845 joint) |
| Citations | 610,269 | 223,983 | 803,550 |
| Faculty with papers | 720 | 159 | 879 |
| Papers with > 12 authors (instructor's flag) | 1,698 | 2,112 | 3,119 |
| Nature Index papers | 2,345 | 1,375 | 3,207 |

## 3. Getting started

### 3.1 Requirements
- Python 3.11 (3.10+ should work). Install the packages with `python -m pip install -r requirements.txt`. On macOS/Linux use `python3`.
- Internet access on the first build. It downloads the SCImago data (~30 MB) and the two chart libraries embedded in the dashboard, all pinned versions, and caches them in `data/external/`. No API key is needed to build.

### 3.2 Get the data — choose ONE option

The raw OpenAlex data (`data/raw/`, 66 MB) and the API cache (`data/cache/`, ~0.5 GB) are **not in git**. A fresh clone has the code, the reference lists (`data/external/`) and the last generated outputs, but **cannot rebuild** until `data/raw/` is present.

**Option A — shared snapshot (recommended, identical numbers, no API key needed)**
1. Download `group18_data_raw_2026-10-20.zip` (~68 MB) from the team's shared folder. Soham shares it; link: `<add link here>`.
2. Unzip it into `data/`. It contains one folder, `raw/`, with 16 files.
   ```bash
   unzip group18_data_raw_2026-10-20.zip -d data                          # Git Bash, macOS, Linux
   Expand-Archive group18_data_raw_2026-10-20.zip -DestinationPath data   # PowerShell
   ```
   Check that `data/raw/works_IISc.jsonl.gz` exists. If you extract with a file manager instead, move the `raw` folder into `data/`.
3. Run `python run.py build` (~4–5 minutes; the first run adds ~1 minute for downloads).
4. Check: `git status` should show no changes in `outputs/` or `dashboard/`. You then have exactly the team's numbers.
5. Open `dashboard/index.html` in a browser.

Tested on 20 Oct 2026: a fresh clone plus this zip, without an API key, rebuilt every output file identical to the main copy.

**Option B — collect the data yourself (hours; numbers will differ slightly)**
1. Create a free OpenAlex API key at https://openalex.org/settings/api.
2. Put it in `openalex_key.txt` in the repo root (git-ignored; one key per line, so several teammates' keys can be pooled).
3. Run `python run.py fetch`, then `python run.py build`, then `python run.py fetch --steps profiles`, then `python run.py build` again.
4. Set `DATA_COLLECTED` in `config.py` to your fetch dates; the dashboard shows it.

### 3.3 Everyday commands
```bash
python run.py build                         # rebuild everything from data/raw (no API calls)
python run.py fetch --steps sources         # run one fetch step (cached, resumable)
python run.py fetch --max-calls 500         # cap API calls for this run
DPCN_SAMPLE=1 python run.py build           # experiments: writes to *_sample folders, real outputs untouched
```

## 4. How the pipeline works

```
OpenAlex API ──fetch──> data/cache/ (every response, gzip)  ──> data/raw/*.jsonl.gz
                                                                   │
data/external/ (rosters, CORE, Nature Index list, SJR, JS libs) ───┤
                                                                   ▼
                     build.build_all()        tables t (papers, authorships, faculty, flows, …)
                     networks.build_networks  citation + co-authorship networks, Indian connections
                     stats.compute_stats      everything the dashboard shows (+ journals.py, reputable.py)
                     variants.*               the same again without flagged papers + comparison
                     dashboard.write_dashboard  one self-contained HTML file
                                                                   ▼
                     outputs/ (CSV deliverables), outputs/without_flagged/, dashboard/index.html,
                     data/processed/stats.json (+ stats_without_flagged.json, papers.pkl)
```

### 4.1 Fetch steps (`python run.py fetch --steps …`)

The default runs every step except `inflow_agg`, in this order. A free key gives ~$1/day ≈ 10,000 list calls; single-record lookups are free. If the budget runs out, the run stops cleanly; rerun later and the cache makes it resume where it stopped.

| Step | What it collects | Approx. cost |
|---|---|---|
| `corpus` | IISc and TIFR works 2016–2026 (article, review, letter, book chapter, conference paper) → `works_{inst}.jsonl.gz` | ~480 list calls |
| `fullauthors` | full author lists for 1,435 works the list API cut at 100 authors → `full_authorships.jsonl.gz` | free lookups |
| `sources` | metadata for 6,057 journals/venues: impact, publisher, open access, country → `sources.jsonl.gz` | ~120 calls |
| `relevance` | SDG tags, top-1%/10% flags, India terms from titles/abstracts → `relevance.jsonl.gz` | ~850 calls |
| `authors` | OpenAlex profiles (career h-index) of authors with ≥ 3 papers → `authors.jsonl.gz` | ~140 calls |
| `partners` | subfield profiles of 433 partner institutions → `partner_topics.jsonl.gz` | ~430 calls |
| `outflow` | Indian works our papers cite → `outflow_{inst}.jsonl.gz` | ~1,400 calls |
| `inflow` | Indian works citing our papers → `inflow_{inst}.jsonl.gz` | ~1,400 calls |
| `flows_new` | flows for papers that joined the corpus after the flow fetch | ~25 calls |
| `patents` | patents citing our papers, from Reliance on Science v64 (Zenodo) → `patent_citations.csv.gz` | no API calls; streams a 2.5 GB file (~5 min download). `DPCN_PATENT_FILE=<path>` uses a local copy |
| `profiles` | profiles of matched faculty still missing one (needs `outputs/faculty_list.csv`) | free lookups |
| `inflow_agg` | optional, cheaper aggregate in-flow | ~700 calls |

Wall time: flows and relevance pages are large (references, abstracts), so expect roughly 15–20 calls a minute. A full fetch takes several hours. Run long fetches in the background.

### 4.2 Build stages (`python run.py build`, ~4 min)
1. **`build.build_all()`** loads the corpus, applies full author lists, and decides each paper's institutions. TIFR counts only for Mumbai authors.
   - Adds SJR quartile, CORE rank, journal impact, Nature Index and flagship flags, SDG and India-focus fields, and the collaboration type.
   - Matches roster faculty to OpenAlex author IDs, adds former faculty by rule, and computes per-faculty metrics.
   - Drops papers with no identifiable IISc/TIFR author.
   - Writes `group18_data.csv` and `faculty_list.csv`.
2. **`networks.build_networks()`** builds the citation network (PageRank) and the Indian citation flows. It also builds the co-authorship network (faculty; degree, betweenness, Louvain) and the Indian connections table.
3. **`stats.compute_stats()`** computes everything the dashboard shows, including `journals.journal_stats()` and `reputable.reputable_stats()`. It writes `data/processed/stats.json` and `outputs/stats/*.csv`.
4. **`variants.without_flagged()`** repeats stages 2–3 without the flagged papers into `outputs/without_flagged/`. **`variants.compare()`** writes `outputs/stats/with_vs_without_flagged.csv`.
5. **`dashboard.write_dashboard()`** injects both statistics sets and the comparison into the template and embeds the JS libraries.

## 6. Data model

### 6.1 Identifiers
- OpenAlex short IDs: `W…` (work), `A…` (author), `I…` (institution), `S…` (source/journal).
- `N:<name-tokens>`: an author OpenAlex has not given an ID. It is folded into a real `A…` ID when exactly one real ID with that name exists at the institute.
- Faculty "person" keys: `R:<inst>:<row>` for an official roster entry (may cover several OpenAlex IDs), and `H:<inst>:<author_id>` for former faculty found by the rule.

### 6.2 The tables dict `t` (returned by `build.build_all()`)

| Key | Content |
|---|---|
| `papers` | DataFrame, one row per paper (index `work_id`), 43 columns, see below |
| `auth` | every authorship (work, author, position, corresponding flag, institutions, Indian institutions, parsed department) |
| `own_auth` | IISc/TIFR authorships, one row per (authorship, institute), with `person` (faculty key or empty) and `senior` |
| `persons` | dict person key → name, inst, department, designation, `faculty_source`, `author_ids` |
| `faculty` | per-faculty metrics = `outputs/faculty_list.csv` |
| `works`, `homes` | raw OpenAlex records; work → set of our institutes (`{"IISc"}`, `{"TIFR"}` or both) |
| `flows` | `{("outflow"|"inflow"|"inflow_agg", inst): records}` of Indian citing/cited works |
| `inst_meta` | institution ID → (name, type, country) |
| `roster`, `profiles`, `dataset` | roster table, author profiles, the `group18_data.csv` rows |

**`papers` columns:**
- **Bibliographic:** `doi`, `title`, `year`, `venue`, `venue_type` (journal / conference / other), `source_id`, `citations`, `fwci`, `domain`/`field`/`subfield`/`topic`.
- **Authors and flags:** `n_authors`, `is_mega` (> 50), `many_authors` (the > 12 flag), `homes`.
- **Quality:** `sjr_quartile`, `sjr`, `core_rank`, `quartile`.
- **Journal:** `journal_impact` (OpenAlex 2-year mean citedness), `publisher`, `journal_country`, `oa_journal`, `apc_usd`, `nature_index`, `flagship`.
- **Collaboration:** `collaboration` (Within IISc/TIFR only / With other Indian institutes / International), `indian_inst_ids`.
- **Relevance:** `sdgs`, `top_sdg`, `india_terms`, `india_focus`, `top10_pct`, `top1_pct`.

### 6.3 `data/processed/stats.json` (what the dashboard reads)
Top-level keys:
- `meta`
- `inst` (per IISc / TIFR / All: kpis, trend, core, top_journals, most_cited, many_authors_by_year, fields, subfields, departments, h_values)
- `flagged`, `faculty`, `citation`, `flows`, `authorship`, `connectivity`
- `journals` (per inst plus `regression`, `network`)
- `reputable` (per inst plus `papers`)
- `impact` (per inst plus `evidence`, `cases`, `settings`)

`stats_without_flagged.json` has the same shape.

## 7. The analyses and their settings

All thresholds live in `config.py`. Change them there and rebuild. Every definition and its source is written up in the README:
- §3.2: pipeline and methods
- §3.4: reputable journals and impact on India, with references
- §6: design decisions

| Analysis | Definition (short) | Setting |
|---|---|---|
| Scope | IISc + TIFR Mumbai; TIFR-centre authors excluded by affiliation text | `INSTITUTIONS`, `TIFR_CHILD_CENTRES`, `TIFR_CENTRE_PATTERN` |
| Publication types | article, review, letter, book chapter, conference paper; no preprints | `WORK_TYPES`, `CONFERENCE_TYPES` |
| Faculty | official rosters (IISc Directory 2025-26, CSP page, IISc retired list; TIFR department pages) matched by name and department; former faculty by rule | `FACULTY_MIN_*` |
| Large-team flag | `authors_gt_12` = more than 12 authors | `AUTHOR_FLAG_THRESHOLD` |
| Mega-collaborations | > 50 authors: excluded from the co-authorship network | `MEGA_AUTHOR_THRESHOLD` |
| Quartile / rank | SJR best quartile in the publication year; CORE 2023 | `lookups.py` |
| Journal impact | OpenAlex 2-year mean citedness (impact-factor equivalent); high-impact = ≥ 10 | `HIGH_IMPACT_THRESHOLD` |
| Journal ecosystems | journals with ≥ 15 of our papers, linked by shared faculty, Louvain | `JOURNAL_NETWORK_MIN_PAPERS` |
| Reputable journals | Nature Index list (178), with its article rules for PR A/B/D, MNRAS, A&A; flagship = Nature, Science, Cell, PNAS | `data/external/nature_index_journals.csv`, `build.nature_index_paper` |
| Research uptake in India | Indian citations (self-citation excluded), share, breadth, reach beyond elite, speed, Indian Citation Index, Indian co-authors | `reputable.py` |
| Impact beyond research | Patents citing the papers (confidence ≥ 4; data to 2023; no Indian Patent Office); co-authorship with companies in India (registry type + address text), ownership, IISc start-ups; co-authorship with / citation by sectors (space, defence, atomic energy, earth & climate, agriculture, health, CSIR, government, NGOs); 23 case studies, each with sources and an evidence level. To add one, append it to `impact_case_studies.json` (facts only from fetched sources; `match` rules: company, faculty, title, title_re, india_term, doi, inst, exclude_doi; a list = any of them; `null` = no paper) | `impact.py`, `PATENT_*` in config, `data/external/impact_case_studies.json` |
| India-focused / SDG | India terms in title/abstract; OpenAlex SDG score ≥ 0.8 | `fetch.INDIA_TERMS`, `SDG_MIN_SCORE` |
| Partners and topic similarity | Indian institutions in author lists; subfield Jaccard for partners with ≥ 10 shared papers | `MIN_SHARED_FOR_TOPICS` |

**Caveats to keep in mind when writing the report:**
- Journal impact is not field-normalised (physics and maths journals score lower).
- Faculty rank is the current (2025-26) title.
- About 29% of papers have no abstract, so they are judged "India-focused" from the title alone.
- Policy, patent and media impact are not measured.

## 8. The dashboard

- **One file.** `dashboard/index.html` is generated, so never edit it by hand. Edit `pipeline/dashboard_template.html` and rebuild. To regenerate only the HTML after a template change, without a full build:
  ```bash
  python -c "import json, config; from pipeline import dashboard, variants; st=json.load(open(config.PROCESSED/'stats.json',encoding='utf8')); sv=json.load(open(config.PROCESSED/'stats_without_flagged.json',encoding='utf8')); dashboard.write_dashboard(st, sv, variants.compare(st, sv))"
  ```
- **Data in the page.**
  - `DATA_ALL` holds all papers, `DATA_NF` the version without flagged papers, and `COMPARE` the comparison rows.
  - `DATA` points to whichever version the *Flagged* switch selects. **Renderers must read `DATA`** so the switch works.
  - Exception: the Large-team tab reads the flagged-paper list from `DATA_ALL`.
- **State and deep links.** `state = {inst, tab, flag}` is saved in localStorage and can be set by URL hash, e.g. `dashboard/index.html#tab=Journal%20choice&inst=TIFR&flag=out&theme=light`.
- **Tabs (11), story first:** Overview (with *Key findings*, computed live from `DATA`) · Impact on India · Reputable journals & India · Journal choice · Large-team papers · Publications · Faculty · Citation network · Co-authorship network · Indian connectivity · Method.
- **Audience: a visiting professor.** Tabs open with results, not theory. Definitions and references live in collapsible sections on the *Method* tab; a tab keeps at most a one-line hint with a link there (`data-goto="Method"`).
- **Helpers in the template:**
  - `plot(id, traces, layout)` for Plotly charts and `table(id, rows, cols)` for sortable tables;
  - `tiles(id, items)` for the key-number tiles;
  - `short()` / `abbr()` for label shortening with institution abbreviations; `pct()` and `fmt()` for numbers;
  - `instList()` for the institute switch;
  - CSS colour variables `--s1…--s8` (IISc = `--s1` blue, TIFR = `--s2` orange) and `--q1…--q4` for quartiles.

**How to add a panel or analysis**
1. Compute it in Python from the tables `t`, in an existing module or a new one, called from `stats.compute_stats()` and stored under a key of `st`. This way it exists for both variants automatically.
2. If it is a table worth submitting, also write a CSV in `stats.write_stat_tables()` (or in the module, using `out_dir`).
3. Add a `<div class="card …">` with element ids to the right `<section>` in the template, and draw it in that tab's `render…()` function from `DATA`.
4. A new tab also needs an entry in `TABS` and in `RENDER`.
5. Update the **Method** tab text and the **README**, including definitions and sources.
6. Rebuild and **look at it**: render the page or take a screenshot (section 10.3).

**Design rules agreed with Soham**
- Keep the dashboard clean. Each chart lives in one place only. Remove panels **and the statistics behind them** when they are no longer used.
- Every measure shown must be defined, with its source, on the tab or in the README.
- Labels must stay distinct: use `short()`, which abbreviates institution names. Identical bar labels make Plotly merge bars.

## 9. Team workflow and rules

1. **Branches.** Work on a branch per task (`git checkout -b <yourname>/<task>`) and open a pull request into `main`. Keep pull requests small and focused on one analysis.
2. **Generated files.** `outputs/` and `dashboard/index.html` are regenerated by every build and conflict badly. **Commit them only on `main`, after merging, by one person (Soham, the integrator).** In feature branches, commit code and docs only, and discard local regenerations before committing:
   ```bash
   git restore outputs dashboard/index.html
   ```
3. **Never commit:**
   - `openalex_key.txt` or any API key;
   - `data/raw/`, `data/cache/`, `data/processed/`;
   - logs, zip files or scratch files;
   - `QUESTIONS_FOR_PROFESSOR.md` (local team notes).

   `.gitignore` covers these; check `git status` before every commit.
4. **No AI attribution in commits.** Do not add `Co-Authored-By:` trailers for AI tools. The team wants only team members listed as contributors.
5. **Same data for everyone.** Use the shared `data/raw` snapshot. If someone re-fetches, agree on it first, update `config.DATA_COLLECTED`, and share the new zip, so the report and dashboard use one dataset.
6. **API keys are personal.** Each teammate creates their own free key. Keys can be pooled one per line in `openalex_key.txt`; the client switches keys when one runs out. Avoid pasting keys into chats.
7. **Docs travel with code.** If you change a definition, threshold or tab, update the README (public methods) and section 2 of this file in the same pull request.
8. **Python environment.** Install with `python -m pip install -r requirements.txt`. If you add a dependency, add it to `requirements.txt`.

## 10. Guide for AI coding agents

### 10.1 Before you start
- Read this file, then `README.md` §3–§6, then `config.py`. Skim the module you will change.
- Check that `data/raw/` exists. If it doesn't, **stop and ask the user** for the shared data snapshot (section 3.2). Do not start a full fetch on your own.

### 10.2 Do and don't
- ✅ `python run.py build` freely: about 4 minutes, no API calls.
- ⚠️ `python run.py fetch …` spends the user's daily OpenAlex budget and can take hours. **Ask first**, use `--steps` and `--max-calls`, and run it in the background.
- ✅ Put new thresholds in `config.py`, with a comment saying where the number comes from.
- ✅ New statistics go through `stats.compute_stats()`, so the with/without-flagged switch keeps working.
- ✅ Keep the build deterministic. Wherever iteration order can reach an output, iterate in sorted order, and keep Louvain at `seed=42` (section 11, item 11).
- ❌ Don't edit `dashboard/index.html` or anything in `outputs/` by hand. They are regenerated.
- ❌ Don't change scope. Only IISc and TIFR Mumbai; no other groups' institutions as subjects.
- ❌ Don't commit generated files from a feature branch, secrets, or AI co-author trailers (section 9).
- ❌ Don't leave unused statistics or duplicate panels behind (section 8).

### 10.3 Verifying your work
- **Numbers:** read `data/processed/stats.json` or the CSVs in `outputs/stats/` after a build. Compare against the headline numbers in README §3.3.
- **Dashboard:** take a headless screenshot of the tab you changed and look at it. Check for overlapping labels, empty panels and clipped tables.

### 10.4 Windows / Git Bash gotchas (they bit us)
- In bash heredocs, `\b` inside a Python string can end up as a literal backspace character (`\x08`). That silently breaks regexes. Write patch scripts with your file-writing tool instead of inline heredocs. Afterwards check with `grep -c $'\x08' pipeline/*.py` (it should be 0).
- The console encoding is cp1252, so set `PYTHONIOENCODING=utf-8` when printing names or titles.
- The repo may sit in OneDrive. Large rewrites of `data/cache` make OneDrive busy; this is harmless.

## 11. Lessons learned and known pitfalls

1. **The OpenAlex list API shows at most 100 authors per paper.** Big collaborations (CMS, LIGO, ALICE) hide our authors beyond the 100th. The `fullauthors` step fetches complete lists with free single-work lookups. It keeps only Indian authorships plus the true author count, to stay small.
2. **OpenAlex gives many NCBS, NCRA, ICTS and TIFR-Hyderabad authors the main TIFR ID.** `fetch.authorship_insts` drops them using their affiliation text. This removed ~4,400 non-Mumbai papers.
3. **Conference papers have their own OpenAlex type** (`conference-paper`). Missing it once hid ~8,000 papers.
4. **Some authors have no OpenAlex ID.** They are keyed by name (`N:` IDs); otherwise faculty such as Monto Mani lost all their papers.
5. **Mega-collaborations distort partner rankings.** `indian_connections.csv` therefore has both `shared_papers` and `shared_papers_excl_mega`.
6. **Flow batches are fixed 100-paper chunks.** Adding papers shifts every later batch, so the cache misses and calls are repeated. Use the `flows_new` step for papers added later.
7. **Performance.** Regex classification once per citation row (~400,000 rows) made a build take 3 hours. Classify once per unique institution, and memoise helpers (`lru_cache` on department matching). The build should stay at ~4 minutes.
8. **Names.** Unicode dashes, invisible characters and non-Latin scripts break matching. They are normalised; one Devanagari-only "author" paper was dropped as an OpenAlex mis-tag.
9. **Nature Index article rules.**
   - Physical Review A/B/D Letters are recognised by an `L` in the DOI.
   - Editors' Suggestions and A&A Letters cannot be recognised in OpenAlex, so they are not counted (documented undercount).
10. **The SDG classifier is noisy.** OpenAlex documents that scores of 0.5–0.8 are right only about half the time, hence the 0.8 cut-off.
11. **Python randomises set order between runs** (hash randomisation). Iterating a set made PageRank values differ in the 15th digit, and community numbers, row orders and the citation-network sample changed from build to build.
    - Every output-affecting iteration is now sorted. NetworkX subgraph views also iterate in set order.
    - The dashboard shows the data-collection date (`config.DATA_COLLECTED`), not a build timestamp.
    - To check a refactor, build twice with `PYTHONHASHSEED=1` and `PYTHONHASHSEED=2`. Then compare `md5sum` of `outputs/**/*.csv` (63 files), `dashboard/index.html` and `data/processed/stats*.json`. All must match.
12. **Unpinned downloads drift.** The SCImago file was fetched from `sjrdata`'s `master` branch, so a later upstream update would have changed quartiles for anyone building later. It is now pinned to a commit. Pin any new external download the same way.
13. **Patent data has no Indian patents.** Reliance on Science is built from full-text patent collections without the Indian Patent Office, so every Indian-patent measure would be a misleading zero; they were removed. Its `self` column holds `isself` / `notself` / `unkself`, not the values its PDF documents.
14. **Few Indian companies are in the institution registry.** Only ~135 Indian companies are typed "company" in OpenAlex. Start-ups (Agnit, PathShodh, Theranautilus, …) appear only in the authors' address text, so `impact.company_from_text` reads it. Each `;`-separated affiliation is read on its own, or a company and IISc listed by one author get merged.
15. **OpenAlex sometimes attaches every institution to every author** of a paper (e.g. the 2019 *BAMS* "Monsoon Mission" paper). Such papers can be wrongly attributed to IISc/TIFR. The monsoon case study excludes that paper (`exclude_doi` in `impact_case_studies.json`).

## 13. Troubleshooting

| Symptom | Fix |
|---|---|
| `STOPPED: OpenAlex daily budget exhausted` | Wait for the reset at midnight UTC (05:30 IST), or add another key line to `openalex_key.txt`. Everything fetched so far is cached. |
| `ModuleNotFoundError` (pyreadr, statsmodels, …) | `python -m pip install -r requirements.txt` with the same `python` you run the code with. |
| Build fails to download SJR data or the JS libraries | Check your internet connection. Or copy `data/external/sjr_journals.rda` and `data/external/vendor/` from a teammate. |
| `UnicodeEncodeError` on Windows | `set PYTHONIOENCODING=utf-8` (cmd) or `export PYTHONIOENCODING=utf-8` (Git Bash). |
| Your numbers differ from README §3.3 | You built from different raw data. Use the shared snapshot (section 3.2). |
| After a build, `git status` lists every CSV as changed, but `git diff --ignore-cr-at-eol --stat` shows nothing | Line endings only (Windows). Run `git config core.autocrlf true`, then `git restore outputs dashboard/index.html` and rebuild. |
| The dashboard shows "No data available" in a panel | That statistic is missing from `stats.json`. Rebuild, and check that the panel reads `DATA`. |
| GitHub Pages link shows 404 | Pages is off. Repo Settings → Pages → Deploy from branch `main`, folder `/ (root)`. |
| Build suddenly very slow | See section 11, item 7; compare stage timings in the build log. |
